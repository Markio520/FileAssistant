## 新电脑启动

使用 Windows x64；本机已验证 Windows 11。安装 Git 与 `global.json` 所要求的 .NET SDK（当前 10.0.403）。WinUI 模板无需重装；NuGet 依赖和构建工具随构建还原。首次构建需联网，并通过脚本下载、校验固定版本 Everything 便携引擎，不用另装用户版 Everything。

新检出在 PowerShell 执行：

```powershell
git clone https://github.com/Markio520/FileAssistant.git
cd FileAssistant
dotnet --version
.\scripts\test.ps1
.\scripts\build.ps1
.\scripts\run.ps1 -Unpackaged
```

若另一台电脑已有检出，确认该处没有未处理的改动后执行 `git pull --ff-only origin main`。本次源文件均在仓库内，不依赖旧机器的绝对源码路径。

非打包方式不要求 Windows 开发者模式；首次全盘索引的专用服务由 Windows 正常请求授权。不授予时仍可用指定目录搜索。不要提升整个主界面，也不要改用用户个人安装的 Everything。更多环境说明见 [development-environment.md](development-environment.md)。`check-environment.ps1` 还会检查独立 WinApp CLI，属于扩展工具检查，并非上述非打包运行的独立安装前置。

`artifacts/`、`bin/`、`obj/`、本机索引、测试样本和截图不提交。搜索设置位于 `%LOCALAPPDATA%\FileAssistant\search-settings.json`，不是仓库配置；新电脑默认从自己的设置与索引开始。不要把个人索引或路径清单放入 GitHub。若需要 UI 样本，在新电脑的 `artifacts/` 下自行生成少量文件。

## 下一次验收顺序

1. 从最新源码重新启动，确认暂存区只有“文件信息”标签；复制功能仍有“操作参数”。关闭旧运行实例再构建，避免 DLL 占用。
2. 用隔离测试文件检查选择多个文件、单个文件夹、资源管理器拖入、复制文件后粘贴、逐行完整路径粘贴；检查 Ctrl+V 不抢输入框的普通文字粘贴。
3. 搜索选中项加入暂存区；重复、失效、无效路径分别核对数量和明细；无效项不应清掉已有文件。
4. 暂存区通过“用于功能”分别转交选中项与全部项，核对数量。复制功能独立添加已有文件，再“从暂存区导入”；默认没有选择时不能导入，显式全选后应追加并去重。
5. 两边分别移出/清空，确认另一个列表和原文件均保留；验证功能“加入暂存区”是显式操作；取消读取后，迟到结果不得回填或覆盖新结果。
6. 标准/紧凑窗口、浅/深色下检查长路径、反馈摘要、导入明细和键盘焦点；前两步尚未完整原生复验的常用条件及跨重启恢复一并补验。

优先修实际验收发现的问题，完成后更新本文件与专项记录，再继续用户确定的下一步。
